# Рабочий процесс

Перед началом задачи:

- проверить список документов в `.agents` и `.codex`;
- прочитать релевантные правила из `.agents`;
- прочитать релевантный контекст из `.codex`, если он нужен для задачи;
- понять, какие файлы и документы затрагивает запрос;
- если пользователь попросил показать diff перед изменениями, подготовить diff и дождаться разрешения.

После подготовки:

- внести изменения;
- проверить состояние проекта;
- запустить подходящие проверки или явно объяснить, почему они не запускались;
- проверить необходимость обновления документации;
- обновить только затронутые документы, если изменение влияет на функциональность, структуру, проверки, GitLab-синхронизацию, окружение или правила;
- после внесения изменений и проверок показать итог изменений;
- в итоговом сообщении кратко перечислить измененные файлы и выполненные проверки;
- текст коммита давать только если пользователь попросил подготовить commit message.

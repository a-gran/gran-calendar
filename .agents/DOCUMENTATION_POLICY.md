# Правила обновления документации

После каждого изменения нужно проверить, требуется ли обновление документации.

Документацию нужно обновлять, если изменение влияет на:

- функциональность Calendar Planner;
- структуру проекта;
- команды запуска и проверки;
- модель события;
- SQLite-хранилище;
- интерфейс календаря;
- будущую GitLab-синхронизацию;
- правила работы Codex;
- известные ограничения.

Если изменение не влияет на документацию, нужно явно указать это в финальном ответе.

Обновлять нужно только затронутые документы, а не всю документацию подряд.

Основные документы:

- `README.md` - короткое описание и быстрый запуск;
- `docs/usage.md` - инструкция пользователя;
- `docs/hotkeys.md` - горячие клавиши;
- `docs/architecture.md` - архитектура;
- `docs/gitlab-sync.md` - будущая синхронизация;
- `.agents/*.md` - правила работы Codex;
- `.codex/*.md` - проектный контекст и рабочие заметки для Codex.
